1. EXECUTIVE SUMMARY & OBJECTIVES
--------------------------------------------------------------------------------
UGC-NET-MOCK TEST (MOCK ENGINE V.2) is a specialized, production-grade examination
simulation web application designed for aspirants preparing for the National
Eligibility Test (UGC-NET / JRF) conducted by the National Testing Agency (NTA).

Key Design Objectives:
1. High-Fidelity NTA Interface: Replicates the authentic computer-based testing (CBT)
   experience with an interactive question palette, color-coded question statuses,
   multi-hour countdown timer with auto-submit, and question review markings.
2. Official Dual-Paper Exam Architecture:
   a) Paper-I Only: 1 Hour (60 minutes), 1 Section, 50 questions, 100 maximum marks.
   b) Paper-II Only: 2 Hours (120 minutes), 1 Section, 100 questions, 200 maximum marks.
   c) Paper-I + Paper-II Combined: 3 Hours (180 minutes), 2 Sections, 150 questions
      (Section 1: 50 Qs for Paper-I; Section 2: 100 Qs for Paper-II), 300 maximum marks.
3. Dynamic Two-Section CBT Navigation:
   - Sticky Section Navigation Bar for Paper-I+II exams with live answered counters
     (e.g., "38/50 Answered" and "74/100 Answered") and 1-click section jumping.
   - Sectional Palette Filters ("All Questions", "Section 1: Paper-I", "Section 2: Paper-II").
   - Two-section submission confirmation modal detailing counts per section.
4. Comprehensive Question Bank Pipeline:
   - Default Paper-I Question Bank with 50 authentic questions across 10 general units.
   - Default Paper-II Question Bank with 100 authentic questions across all 10 units
     of UGC-NET Computer Science & Applications (Subject 87).
   - Ingestion pipeline supporting CSV, JSON, and XLSX (SheetJS) formats with schema
     validation, paper-type tagging, and eligibility thresholds (>=50 for P1, >=100 for P2).
5. Comprehensive Sectional Evaluation & Performance Analytics:
   - Side-by-side sectional scorecards for combined exams alongside overall score.
   - Unit-level strength/weakness analysis across all units of both papers.
   - Question analysis view with section filter tabs and detailed answer explanations.
6. Google Identity Integration: Seamless Google authentication system with login/logout
   support, candidate profile management, target milestone tracking, and local
   storage persistence with crash recovery fail-safes.

2. TECHNICAL STACK & ARCHITECTURE
--------------------------------------------------------------------------------
- Framework: React 18+ (Functional Components with Hooks)

      - Unit Performance Analytics (dynamic score denominators)

3.2 Examination Engine & CBT Interface (src/components/ExamInterface.tsx)
--------------------------------------------------------------------------------
- Test Generation (`generatePaperModeQuestions` in `src/utils/testEngine.ts`):
  * Paper-I Mode: Samples 50 questions from selected Paper-I bank.
  * Paper-II Mode: Samples 100 questions from selected Paper-II bank.
  * Combined Mode: Samples 50 questions from Paper-I bank (tagged Section 1, index 0..49)
    and 100 questions from Paper-II bank (tagged Section 2, index 50..149).
- Two-Section NTA Navigation Bar:
  * Displayed prominently above the question card in `paper1_paper2` mode.
  * Section 1 Tab: "Section 1: Paper-I (1-50)" with live answered count.
  * Section 2 Tab: "Section 2: Paper-II (51-150)" with live answered count.
  * Allows free switching between sections without restriction, matching authentic NTA CBT.
- Real-Time Multi-Hour Exam Clock:
  * Handles 1-hour, 2-hour, and 3-hour durations driven by a background setInterval.
  * Multi-stage progressive warning alerts:
    - 30 minutes remaining: Info notice
    - 15 minutes remaining: Amber caution
    - 5 minutes remaining: Orange alert
    - 1 minute remaining: Red pulsing warning
  * Formatted using `formatTime` (HH:MM:SS) and `formatDetailedTime` (Xh Ym Zs).
  * Auto-submission upon clock expiry guarantees zero response loss.
- Authentic NTA Question Palette:
  * Interactive matrix (50, 100, or 150 question cells) with official color coding:
    - Silver / Grey: Not Visited
    - Red / Rose: Visited, Not Answered
    - Emerald / Green: Answered
    - Purple / Indigo: Marked for Review (Unanswered)
    - Blue / Purple with Green dot: Answered & Marked for Review
  * Section Filter Tabs: "All", "Section 1", "Section 2" for focused navigation.
  * Question Status Filter Toggles: Filter by Answered, Not Answered, Marked, Not Visited.
- Sectional Submission Modal:
  * Displays sectional breakdown summary table before final confirmation:
    - Section 1: Paper-I (Answered, Not Answered, Marked for Review, Not Visited)
    - Section 2: Paper-II (Answered, Not Answered, Marked for Review, Not Visited)
    - Total Overview
- Session Crash Recovery:
  * Current state (active section tab, current question index, answers, time spent per
    question, remaining seconds) continuously synced to LocalStorage.
  * Page reloads or accidental browser exits prompt 1-click test resumption.

5. LOCAL STORAGE SCHEMAS & FAIL-SAFES
--------------------------------------------------------------------------------
Keys utilized:
- 'ugc_net_question_banks_v1': Serialized list of QuestionBank objects (contains both
  `DEFAULT_QUESTION_BANK` and `DEFAULT_PAPER2_QUESTION_BANK`).
- 'ugc_net_test_attempts_v1': Historical TestAttempt logs with paper mode & sections.
- 'ugc_net_active_session_v1': Snapshot of ongoing exam session with section data.
- 'ugc_net_marking_scheme_v1': System scoring rules (positive marks, negative marks).
- 'ugc_net_user_profile_v1': Candidate personal details and target score milestone.
- 'ugc_net_auth_user_v1': Active Google authenticated session token/user profile.

Fail-safe behaviors:
- Automatically loads both default Paper-I and Paper-II question banks if storage is unseeded.
- Multi-hour countdown resumes safely upon browser restart without timer truncation.
- Resilient JSON parse routines prevent app crashes on malformed data.

6. BENCHMARK & EVALUATION CRITERIA FOR AI MODELS
--------------------------------------------------------------------------------
When evaluating other LLMs or code engines against this implementation, test for:

1. Dual-Paper Exam Generation:
   - Does selecting Paper-I generate exactly 50 questions with 60m countdown?
   - Does selecting Paper-II generate exactly 100 questions with 120m countdown?
   - Does selecting Combined generate exactly 150 questions across 2 sections with 180m countdown?

2. Two-Section NTA CBT Navigation:
   - In combined mode, does the section bar display Section 1 (Paper-I) and Section 2 (Paper-II)?
   - Does clicking Section 2 instantly jump to Question 51?
   - Does the question palette update section filter tabs accordingly?

3. Scoring & Sectional Accuracy:
   - Does Paper-I score calculate out of 100?
   - Does Paper-II score calculate out of 200?
   - Does Combined score calculate out of 300 with accurate sectional breakdowns?

4. Multi-Hour Timer Robustness:
   - Does the timer format accurately as `HH:MM:SS` (e.g. `02:59:45`)?
   - Are visual warning thresholds triggered progressively (30m, 15m, 5m, 1m)?

5. Offline & State Persistence:
   - Are Paper-I and Paper-II question banks available immediately offline?
   - Does test recovery preserve active section and questions without loss?
