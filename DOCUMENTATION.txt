1. EXECUTIVE SUMMARY & OBJECTIVES
--------------------------------------------------------------------------------
UGC-NET-MOCK TEST (MOCK ENGINE V.2) is a specialized, production-grade examination
simulation web application designed for aspirants preparing for the National
Eligibility Test (UGC-NET / JRF) conducted by the National Testing Agency (NTA).

Key Design Objectives:
1. High-Fidelity NTA Interface: Replicates the authentic computer-based testing (CBT)
   experience with an interactive question palette, color-coded question statuses,
   countdown timer with auto-submit, and question review markings.
2. Official Exam Pattern: Exactly 50 multiple-choice questions (MCQs) drawn from 10
   prescribed UGC-NET Paper I syllabus units, evaluated under a 60-minute countdown
   with 2 marks per correct response and zero negative marking (configurable).
3. Question Bank Operations: Comprehensive ingestion pipeline supporting CSV, JSON,
   and XLSX formats with schema validation, duplicate detection, and category sorting.
4. Comprehensive Performance Analytics: Post-exam breakdown with accuracy percentage,
   unit-by-unit strength/weakness analysis, time spent per question, and full
   explanation reviews.
5. Google Identity Integration: Seamless Google authentication system with login/logout
   support, candidate profile management, target milestone tracking, and local
   storage persistence.

3.2 Examination Engine (src/components/ExamInterface.tsx & src/utils/testEngine.ts)
- Test Generation:
  * Pulls random or sequential 50 questions from selected question bank.
  * Shuffles question order to eliminate pattern bias.
- Real-Time Exam Clock:
  * 60-minute countdown (3600 seconds) driven by background setInterval.
  * Visual warnings at 5 minutes and 1 minute remaining.
  * Automatic submission upon clock expiry without loss of answers.
- NTA Question Palette:
  * Interactive 50-grid matrix with official color codes:
    - Silver/Grey: Not Visited
    - Red/Rose: Visited, Not Answered
    - Emerald/Green: Answered
    - Purple/Indigo: Marked for Review (Unanswered)
    - Blue/Purple with Green dot: Answered & Marked for Review
  * Quick filter toggles to view questions by status.
- Question Actions:
  * "Save & Next": Saves selected option and advances to next question.
  * "Mark for Review & Next": Flags question for later re-checking and advances.
  * "Clear Response": Unselects current chosen radio option.
  * "Previous" / "Next" pagination buttons.
- Fail-Safe & Crash Recovery:
  * Active session continuously saved to LocalStorage on every question change.
  * Browser reloads or accidental navigation automatically prompts to resume test.

6. SUPABASE BACKEND ARCHITECTURE & 10-YEAR EXCEL ARCHIVES
--------------------------------------------------------------------------------
The application supports seamless transition to a relational Supabase PostgreSQL backend
for community-shared 10-year question archives.

6.1 Environment Variables:
- VITE_SUPABASE_URL: Project URL (e.g., https://your-project.supabase.co)
- VITE_SUPABASE_ANON_KEY: Project Anonymous Public API Key

6.2 Relational Schema (PostgreSQL with RLS):
Tables:
1. `question_banks` (Parent table):
   - id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
   - name: TEXT NOT NULL (Archive / Shift title)
   - exam_year: INTEGER NOT NULL (e.g. 2014-2024)
   - uploaded_by: TEXT DEFAULT 'Anonymous Aspirant'
   - created_at: TIMESTAMPTZ DEFAULT now()
   - description: TEXT
   - total_questions: INTEGER DEFAULT 0

2. `questions` (Child table with Foreign Key):
   - id: UUID PRIMARY KEY DEFAULT gen_random_uuid()
   - bank_id: UUID NOT NULL REFERENCES question_banks(id) ON DELETE CASCADE
   - question_text: TEXT NOT NULL
   - option_a: TEXT NOT NULL
   - option_b: TEXT NOT NULL
   - option_c: TEXT NOT NULL
   - option_d: TEXT NOT NULL
   - correct_answer: TEXT NOT NULL CHECK (correct_answer IN ('A', 'B', 'C', 'D'))
   - explanation: TEXT
   - unit: TEXT DEFAULT 'General Teaching & Research Aptitude'
   - difficulty: TEXT DEFAULT 'Medium' CHECK (difficulty IN ('Easy', 'Medium', 'Hard'))
   - created_at: TIMESTAMPTZ DEFAULT now()

Row Level Security (RLS) Policies:
- Public Read: Allows all users to query verified archives.
- Public Insert: Allows community aspirants to upload 10-year question sets.
- Foreign Key Integrity: Ensures questions can only be inserted for valid parent banks.

6.3 Two-Step Database Insert Pipeline:
1. Step 1: Inserts the bank header row into `question_banks` using .insert({...}).select('id').single().
2. Step 2: Extracts the generated parent bank UUID and maps it to all validated question rows as `bank_id`.
3. Step 3: Inserts all questions into `questions` table in batches. If Step 2 fails, auto-rolls back orphan records.

6.4 Excel Validator & Ingestion Rules:
- Columns required: Question, Option A, Option B, Option C, Option D, Correct Answer.
- Strict Answer Key validation: Case-insensitive check enforcing only values in ['A', 'B', 'C', 'D'].
- Pre-built downloadable template: `UGC_NET_Paper1_10Year_Archive_Template.xlsx`.

7. BENCHMARK & EVALUATION CRITERIA FOR AI MODELS
--------------------------------------------------------------------------------
When evaluating other LLMs or code engines against this implementation, test for:

1. State Integrity & Recovery:
   - Does the test state survive browser refresh without resetting the timer to 60m?
   - Are user answers and marked-for-review flags preserved precisely?

2. NTA Palette Logic Accuracy:
   - Is an unvisited question correctly marked silver?
   - Visited but unanswered marked red?
   - Answered marked green?
   - Answered + Marked for review marked purple with green indicator dot?

3. Scoring Accuracy:
   - Correct answers = correct_count * marks_per_correct.
   - Negative marking correctly deducted if configured > 0.
   - Accuracy strictly calculated as correct_count / (correct_count + incorrect_count).

4. Component Architecture & Cohesion:
   - Are repetitive cards unified into clean single components (e.g. Performance Summary)?
   - Are secondary navigation elements neatly housed within the Profile dropdown?
   - Is authentication state reactively synchronized between Header, Profile, and Modals?

5. Type Safety & Zero-Error Compilation:
   - Does `tsc --noEmit` pass with zero type errors?
   - Are all nullable states handled without runtime exceptions?
